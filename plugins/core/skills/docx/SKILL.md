# DOCX Documents

Use this skill when the task involves `.docx` files. A DOCX is a ZIP archive with OOXML XML files; simple work should stay simple, and complex legal/track-changes work should be handled conservatively.

## Decision tree

1. **Read/analyze only** → extract to Markdown/text first.
2. **Create a new document** → generate from Markdown/HTML with `pandoc` when available, or use `python-docx` for structured output.
3. **Simple edit to your own generated document** → use `python-docx` or direct OOXML only for the targeted change.
4. **Third-party/legal/business document with tracked changes/comments** → preserve original, unpack OOXML, inspect comments/tracked-change tags, and make the smallest possible edit. When uncertain, return a proposed patch/summary instead of destroying metadata.

## Reading

Prefer:

```bash
pandoc input.docx -t markdown -o /tmp/input.md
```

Fallback without pandoc:

```python
from docx import Document

doc = Document('input.docx')
for p in doc.paragraphs:
    print(p.text)
```

For comments/tracked changes or embedded media, inspect OOXML:

```bash
mkdir -p /tmp/docx-unpack
python3 - <<'PY'
import zipfile
zipfile.ZipFile('input.docx').extractall('/tmp/docx-unpack')
PY
```

Key files:
- `word/document.xml` — body
- `word/comments.xml` — comments
- `word/media/` — images
- `<w:ins>` / `<w:del>` — tracked insertions/deletions

## Creating

For prose documents, start from Markdown and convert:

```bash
pandoc report.md -o report.docx
```

For programmatic documents:

```python
from docx import Document

doc = Document()
doc.add_heading('Title', level=1)
doc.add_paragraph('Body text')
doc.save('output.docx')
```

## Editing

- Always keep an untouched copy of the original.
- Prefer high-level `python-docx` for paragraphs/tables you own.
- For comments/tracked changes, inspect OOXML before editing and verify after packing.
- Do not flatten formatting unless the user explicitly accepts that tradeoff.

## Verification

After writing a DOCX:

```bash
python3 - <<'PY'
from docx import Document
Document('output.docx')
print('docx-open-ok')
PY
```

If `pandoc` or LibreOffice is available, also convert back to text/PDF for a visual/content sanity check.

## Output discipline

Report:
- input file and output file paths;
- what was changed/extracted;
- whether comments/tracked changes were preserved, ignored, or not present;
- any formatting risk.

## Hard rules

- Never overwrite the only copy of a user document.
- Never silently accept/reject tracked changes.
- Never promise pixel-perfect Word formatting after a lossy conversion.
- Keep generated documents practical and boring; decorative Word art belongs in the same landfill as autogenerated corporate mission statements.
