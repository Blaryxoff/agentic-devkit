# Pixel Build — Implement UI from References

1. Resolve the target, active plugins, runtime/host, supplied reference, and relevant project components/tokens. Activate `devkit-coder` before any edit.
2. Load `plugins/frontend/conduct/visual-workflow.md` and follow every applicable obligation in reference-implementation mode. Select actual runtime tools through enabled plugin indexes; keep platform mechanics in the selected adapter.
3. Extract a measured design ledger: complete composition/control inventory, boxes, spacing, typography, colors, states, adaptive constraints, and icon/asset details. Resolve required missing assets before substitution.
4. Reuse existing primitives and implement the smallest complete page/screen/component change while preserving public contracts. Cover required loading/error/empty/blocked/partial/success and accessible interactions.
5. Run the adapter's structural/layout audit and reference comparison per target/state/configuration. Verify spacing/token resolution and every icon explicitly; label regression assertions that do not establish design-reference fidelity.
6. Iterate with the workflow's ordered delta triage, focused cell rechecks, and one complete final target pass. Follow its baseline-approval and dependency/test-file authorization rules.
7. Report files, reused/new components/tokens, per-target geometry/accessibility and comparison evidence, remaining deltas, approvals, and unavailable environments. Keep measured manual correspondence distinct from persistent regression protection.

Preserve the supplied reference or approved baseline as the source of truth. Never hide defects with broad thresholds, masks, or unapproved baseline replacement.
