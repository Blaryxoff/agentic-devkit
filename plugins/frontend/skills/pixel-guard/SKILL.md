# Pixel Guard — Safe Visual Changes

1. Resolve the requested scope, active plugins, runtime/host, and affected surfaces. Activate `devkit-coder` before any edit.
2. Load `plugins/frontend/conduct/visual-workflow.md` and follow every applicable obligation in guarded-change mode. Select actual runtime tools through enabled plugin indexes; keep platform mechanics in the selected adapter.
3. Classify visual-preserving refactor/token extraction versus intentional restyle/adaptive correction. Enumerate affected targets/states/configurations and verify current output against each approved baseline before editing.
4. If a baseline is missing, capture the current state and obtain explicit approval before treating it as expected. Resolve missing persistent assertion tooling before claiming regression protection.
5. Make only requested changes, then rerun the adapter's structural/layout audit and deterministic visual assertions. Read mismatch output, inspect live measurements, and use matching diff crops to diagnose unexplained deltas.
6. Restore unintended visual changes without sacrificing intentional ones. Pure refactors require every configured cell to match; present intentional deltas for explicit approval before updating only named baselines.
7. Run focused rechecks during iteration and one complete final target pass. Report files, each cell's audit/assertion/evidence, delta classification/resolution, approvals, risks, and unverified surfaces.

Preserve the supplied reference or approved baseline as the source of truth. Never hide defects with broad thresholds, masks, or unapproved baseline replacement.
